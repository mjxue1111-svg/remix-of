## 需求一：拆分"新增账户"与"绑定账户"

### 1.1 背景与问题

当前"新增 / 绑定星图账户"弹窗只有一套表单，混合了"账户基础信息（账户名称、账户 ID、账户主体、账户类型）+ 联系人信息 + 证明材料"，未区分两种本质不同的业务场景：

- **客户还没有星图账户**：需要米播帮忙新建一个星图账户，此时客户填不出"账户名称 / 账户 ID"（账户尚不存在）。
- **客户已有星图账户，只是想接入本平台**：账户本身已经存在，只需要提交账户信息完成绑定核验，不需要重复提交联系人、证明材料等资料。

一套表单无法很好地覆盖两种场景，容易让"已有账户"的客户被迫填一堆不必要的信息，也可能让"没有账户"的客户误填一个不存在的账户 ID。

### 1.2 需求描述

在原弹窗中增加"新增账户 / 绑定账户"模式切换（Tab / 分段控件），两种模式下展示不同表单：

| 模式 | 使用场景 | 需要填写的信息 |
| --- | --- | --- |
| **新增账户** | 客户首次进入平台且名下没有可用星图账户，需要米播新建账户 | 1. 账户主体（企业主体名称）<br>2. 联系人信息（姓名 *、电话 *、邮箱）<br>3. 账户证明材料（营业执照 / 星图合作证明等，支持 JPG/PNG/PDF） |
| **绑定账户** | 客户已有星图账户，只需接入平台 | 1. 星图账户名称 *<br>2. 星图账户 ID *<br>3. 账户主体 * |

（* 为必填项）

### 1.3 交互流程

1. 客户点击"新增账户"按钮，唤起弹窗，默认展示"新增账户"模式。
2. 客户可通过顶部分段控件在"新增账户 / 绑定账户"间自由切换，切换后表单字段、说明文案、提交确认勾选文案同步变化。
3. 客户填写对应模式下的必填信息，勾选"信息真实有效"确认框后，"提交审核"按钮才可点击。
4. 提交后进入"提交成功"状态：
   - **绑定账户**：展示账户名称 + 账户 ID + 状态"待审核"。
   - **新增账户**：展示账户主体 + 状态"待审核"，并提示"账户名称及账户 ID 将在审核通过后由米播分配"。
5. 后续账户审核通过 / 驳回逻辑与现有"星图账户概览"模块保持一致（待审核 → 正常 / 审核驳回）。

### 1.4 验收标准

- [ ] 弹窗顶部提供"新增账户 / 绑定账户"两个可切换的入口，当前模式有明显的选中态。
- [ ] "新增账户"模式下，表单只包含账户主体、联系人信息（姓名/电话必填，邮箱选填）、证明材料上传，不出现账户名称 / 账户 ID 输入框。
- [ ] "绑定账户"模式下，表单只包含星图账户名称、星图账户 ID、账户主体三个必填项，不出现联系人信息、证明材料模块。
- [ ] 两种模式切换时，已填写内容各自保留（互不清空），说明文案、确认勾选文案、提交成功页展示内容随模式变化。
- [ ] 必填项未填写完整或未勾选确认框时，"提交审核"按钮保持禁用。

## 需求二：消息通知功能

### 2.1 背景与问题

客户端头部已有消息图标（铃铛），但点击无任何反应，客户无法获知账户审核结果、充值进度提醒、返点激励等关键信息，需要主动去各个模块查询，体验割裂。

### 2.2 需求描述

点击客户端头部消息图标，弹出下拉消息面板，展示该客户名下的全部消息通知，覆盖以下典型场景（文案示例，实际以业务侧最终文案为准）：

1. **账户审核结果类**：如"新增账户「云岚直播推广」已审核通过，现已可正常发起充值"。
2. **充值 / 消耗提醒类**：如"本月累计充值已超 100 万元，下次充值可享受额外折扣"。
3. **特批合作提醒类**：如"特批充值订单已处理完成，请按约定时间完成付款，避免影响合作"。
4. **返点激励提醒类**：如"本月充值即将满 100 万元，达标后可领取返点激励"。

### 2.3 交互流程

1. 消息图标右上角展示未读消息数角标（红点 + 数字，超过 9 条显示 "9+"），无未读时不展示角标。
2. 点击图标，弹出下拉面板，面板内展示消息列表（按时间倒序），每条消息包含：类型图标、标题、正文、时间、未读状态点。
3. 面板顶部提供"全部标记为已读"操作，点击后清空未读角标。
4. 点击单条消息即标记为已读（未读态背景高亮 → 点击后变为已读态）。
5. 消息列表为空时展示空状态提示"暂无消息"。

### 2.4 消息类型与样式对应关系

| 类型 | 说明 | 图标 / 主色 |
| --- | --- | --- |
| success（账户审核通过） | 正向结果通知 | 绿色 |
| finance（充值/消耗提醒） | 资金相关提醒 | 蓝色 |
| warning（付款 / 特批提醒） | 需要客户尽快处理 | 橙色 |
| reward（返点激励） | 权益 / 激励类提醒 | 主题蓝紫色 |

### 2.5 验收标准

- [ ] 消息图标存在未读消息时展示数字角标，全部已读后角标消失。
- [ ] 点击图标弹出下拉面板，覆盖需求中列出的四类场景消息各至少一条示例。
- [ ] 支持"全部标记为已读"一键操作。
- [ ] 支持点击单条消息标记为已读。
- [ ] 消息列表可滚动查看（面板最大高度限制，超出部分滚动展示），不撑破页面布局。

## 需求三：客户主体信息内容补充

### 3.1 背景与问题

"我的账号信息"页面的"客户主体信息"模块是客户端本轮开发中新调整的内容，目前工商信息部分仅有客户主体名称、统一社会信用代码、企业状态三项，信息过于单薄，无法支撑销售/运营对客户资质、行业属性、企业规模等信息的判断需要。

### 3.2 需求描述

在"工商信息"区块补充以下字段，并为每个字段标注数据来源标签，标识该字段是否可编辑：

| 数据来源标签 | 含义 | 是否可编辑 |
| --- | --- | --- |
| 工商回显 | 根据客户主体名称自动联动查询工商登记信息回填 | 不可编辑 |
| 人工校正 | 由业务/客户手动维护补充的信息 | 可编辑 |
| 系统记录 | 系统自动生成记录，如资料更新时间 | 不可编辑 |

字段清单：

| 字段 | 数据来源 |
| --- | --- |
| 客户主体名称 * | 工商回显（可编辑以触发重新联动查询） |
| 统一社会信用代码 | 工商回显 |
| 企业状态 | 人工校正 |
| 法人代表 | 工商回显 |
| 企业类型 | 人工校正 |
| 注册资本 | 工商回显 |
| 所属行业 | 人工校正 |
| SOP 行业组 | 人工校正 |
| 行业梯队 | 人工校正 |
| 员工规模 | 人工校正 |
| 注册地址 | 工商回显 |
| 经营地址 | 人工校正 |
| 资料更新时间 | 系统记录 |
| 经营范围 / 企业简介 | 人工校正 |

### 3.3 交互说明

1. 客户主体名称变更（或从候选列表中选择）时，工商回显字段（统一社会信用代码、法人代表、注册资本、注册地址）自动联动查询并回填，不可手动编辑。
2. 人工校正字段由业务/客户手动填写维护，编辑态下为可编辑输入框。
3. 保存后，"资料更新时间"由系统自动刷新为最新保存时间，不可手动修改。

### 3.4 待二期补充事项

企业类型、所属行业、SOP 行业组、行业梯队、员工规模等"人工校正"字段的具体取值范围（下拉枚举选项），本期原型暂以自由文本呈现，**取值范围将在二期 PRD 中补充明确定义**。

### 3.5 验收标准

- [ ] 工商信息区块展示需求 3.2 列出的全部字段，每个字段旁标注数据来源标签
- [ ] "工商回显"字段在编辑态下为禁用（只读）状态，仅能通过客户主体名称联动更新
- [ ] "人工校正"字段在编辑态下可自由编辑
- [ ] "资料更新时间"不可编辑，保存后自动刷新为最新时间
- [ ] 非编辑态下字段以标签 + 值的卡片形式展示，布局清晰、来源标签可辨识

## 需求四：修改个人信息流程简化（取消审核）

### 4.1 背景与问题

旧版"修改个人信息"弹窗需要同时维护联系人姓名/电话/邮箱、填写修改原因，提交后进入"待米播审核"状态，需人工审核通过才能生效。但换绑手机号本身已经通过短信验证码完成了身份核验，再叠加一层人工审核流程冗长且无必要。

### 4.2 需求描述

将"修改个人信息"精简为纯"换绑手机号"流程：客户只需填写新绑定手机号，点击获取验证码，输入验证码校验通过后，点击"确认修改"即可**立即生效**，不再需要米播审核，也不再需要填写联系人信息或修改原因。

### 4.3 交互流程

1. 点击"修改个人信息"，弹出弹窗，展示当前绑定手机号（只读）。
2. 填写新绑定手机号（校验为中国大陆手机号格式，且不能与当前绑定手机号相同）。
3. 点击"获取验证码"，验证码发送至新绑定手机号（原型 mock 验证码为 `123456`）。
4. 输入 6 位验证码，校验通过后显示"验证通过，确认后立即生效"提示。
5. 点击"确认修改"，绑定手机号立即更新，弹出成功提示，弹窗关闭，无需等待审核。

### 4.4 验收标准

- [ ] 弹窗仅包含"当前绑定手机号（只读）/ 新绑定手机号 / 验证码"三项，不再展示联系人姓名、联系人电话、联系人邮箱、修改原因字段
- [ ] 验证码未校验通过前，"确认修改"按钮保持禁用
- [ ] 确认修改后立即更新绑定手机号并提示成功，不再展示"待米播审核"状态、审核详情入口及驳回原因等审核相关 UI
- [ ] "账号与联系人信息"模块中的绑定手机号同步展示为脱敏后的新手机号

> 说明：本次简化后，联系人姓名 / 电话 / 邮箱在该弹窗中不再可编辑，页面上仍以只读形式展示。如后续仍需支持编辑联系人信息，需另行规划独立入口，不在本次范围内。
