## 需求一：新增账户 / 绑定账户拆分为独立入口与弹窗

### 1.1 背景与问题

早期版本中，"新增账户"入口唤起的是同一个弹窗，通过弹窗内的页签在"新增账户"与"绑定账户"两种表单间切换。但两种场景的业务含义、必填字段、提交后的展示内容完全不同，用页签切换容易让客户混淆；同时"绑定账户"并非高频核心操作，没有必要在工作台首页占据入口位置。

### 1.2 需求描述

1. 弹窗拆分为两个完全独立的组件：**新增账户弹窗**与**绑定账户弹窗**，不再有页签或模式切换控件，各自的表单字段、提交流程、成功页均独立。
2. 入口按场景分布：
   - **工作台首页**（欢迎横幅 + "星图账户概览"卡片头部）：仅保留"新增账户"按钮，不展示"绑定账户"。
   - **"我的账号信息"页面**（页面顶部 + "已绑定账户"卡片头部，共两处）：保留"新增账户"与"绑定账户"两个并列按钮。

### 1.3 交互流程

1. 客户点击"新增账户" → 直接打开"新增星图账户"弹窗，填写账户主体、直客ID、联系人信息、账户证明材料后提交。
2. 客户在"我的账号信息"页点击"绑定账户" → 直接打开"绑定星图账户"弹窗，填写星图账户名称、账户 ID、账户主体后提交。
3. 两个弹窗互不感知对方状态，取消或提交其中一个不影响另一个。

### 1.4 验收标准

- [ ] 工作台首页欢迎横幅仅展示"新增账户"与"发起充值"两个按钮
- [ ] "星图账户概览"卡片头部仅展示"新增账户"按钮
- [ ] "我的账号信息"页面顶部与"已绑定账户"卡片头部均展示"新增账户"+"绑定账户"两个独立按钮
- [ ] "新增账户"弹窗内不包含任何模式切换或"绑定账户"页签，反之亦然
- [ ] 两个弹窗的表单字段、提交后成功页展示内容完全独立

## 需求二：新增账户表单字段优化

### 2.1 背景与问题

"新增账户"表单在实际使用中还需要补充直客归属、账户资质证明方式等信息，且个别字段命名需要更贴合业务语境。

### 2.2 需求描述

1. **字段改名**：将"联系邮箱"改为"账号绑定邮箱"。
2. **新增"直客ID"板块**：与"账户主体""联系人信息"同级的独立必填板块。
3. **账户证明材料前置单选**：提交材料前新增"资质证明方式"单选——
   - 选择**银行开户对公**：需填写"开户行（精确到支行）"与"银行卡号"，均为必填。
   - 选择**账户授权**：需填写"可授权的星图账户ID"，必填。
4. **材料说明文案更新**：由"建议上传营业执照、星图合作证明等材料，便于米播快速审核。"更新为"需上传最新版营业执照、商标证、品牌LOGO图片、软著（如有）、游戏版号证明（如有）等材料，便于米播快速审核"。

### 2.3 字段层级

```
新增账户
├─ 账户主体
├─ 直客ID（必填）
├─ 联系人信息
│   ├─ 联系人姓名 * · 联系电话 *
│   └─ 账号绑定邮箱（原"联系邮箱"）
└─ 账户证明材料
    ├─ 资质证明方式 *（单选）
    │   ├─ 银行开户对公 → 开户行（精确到支行）* + 银行卡号 *
    │   └─ 账户授权 → 可授权的星图账户ID *
    └─ 材料上传（说明文案已更新）
```

### 2.4 验收标准

- [ ] "直客ID"作为独立板块展示，与"账户主体""联系人信息"视觉层级一致，为必填项
- [ ] "联系邮箱"字段的标签与占位文案均更新为"账号绑定邮箱"
- [ ] 账户证明材料板块在上传区域之前展示"银行开户对公 / 账户授权"单选
- [ ] 选择"银行开户对公"时展示"开户行（精确到支行）""银行卡号"两个必填输入框
- [ ] 选择"账户授权"时展示"可授权的星图账户ID"必填输入框
- [ ] 未选择资质证明方式或对应必填字段未填写时，"提交审核"按钮保持禁用
- [ ] 材料说明文案更新为新文案

## 需求三：账户审核驳回后重新编辑（保留原内容）

### 3.1 背景与问题

客户提交"新增账户"申请被米播驳回后，此前只能重新打开一个全新的空白表单，账户主体、联系人信息、资质证明方式及已上传的材料都需要重新录入，体验差，也容易因重复填写导致信息前后不一致。

### 3.2 需求描述

在"星图账户概览"模块中，"审核驳回"状态的账户操作列新增**"重新编辑"**按钮：

1. 点击后打开"新增账户"弹窗，弹窗顶部展示**上次驳回原因**。
2. 表单自动带回客户上次提交时填写的账户主体、直客ID、联系人姓名/电话/邮箱、资质证明方式（银行开户对公/账户授权）及对应字段、已上传的证明材料文件列表。
3. 客户可在此基础上修改后重新提交，无需从头填写。

### 3.3 交互流程

1. 客户在"星图账户概览"表格中看到状态为"审核驳回"的账户记录。
2. 点击该记录操作列的"重新编辑"按钮。
3. 弹窗打开，顶部展示红色驳回原因提示；表单各字段与已上传文件均预填为上次提交内容。
4. 客户修改需要调整的信息后，勾选确认并点击"提交审核"，账户重新进入"待审核"状态。

### 3.4 验收标准

- [ ] 仅"审核驳回"状态的账户在操作列展示"重新编辑"按钮，其他状态不展示
- [ ] 点击"重新编辑"后打开的弹窗顶部展示"上次审核驳回原因"提示条
- [ ] 弹窗内账户主体、直客ID、联系人姓名/电话/邮箱、资质证明方式及对应字段均自动预填为上次提交内容
- [ ] 已上传的证明材料文件在文件列表中展示并标注"已上传"，与本次新选择的文件加以区分
- [ ] 客户可基于预填内容直接修改后重新提交，无需重新填写全部字段

## 需求四：消息通知功能

### 4.1 背景与问题

客户端头部消息图标此前点击无任何反应，客户无法获知账户审核进度、充值提醒、返点激励等关键信息，需要主动去各模块查询，体验割裂。

### 4.2 需求描述

点击消息图标唤起下拉面板，展示客户名下全部消息，覆盖以下场景（文案示例，实际以业务侧最终文案为准）：

| 场景 | 参考文案 |
| --- | --- |
| 账户审核发起 | 您新增的星图账户「云岚直播推广」已发起审核，请耐心等候。 |
| 账户审核通过 | 您新增的星图账户「云岚直播推广」已审核通过，现已可正常发起充值。 |
| 账户审核驳回 | 您新增的星图账户「云岚效果推广」被审核驳回，请重新提交材料新建账户。 |
| 充值提醒（超额） | 本月累计充值金额已超过 100 万元，下次充值可享受额外折扣，详情请咨询您的对接人。 |
| 充值提醒（临近达标） | 本月充值金额即将满 100 万元，达标后可获得返点激励，请关注账户余额变动。 |
| 特批合作提醒 | 您的特批充值申请已处理完成，请按承诺时间完成付款并上传凭证，以免影响后续合作。 |

### 4.3 交互流程

1. 消息图标存在未读消息时展示角标（红点 + 数量，超过 9 条显示"9+"），无未读时不展示角标。
2. 点击图标弹出下拉面板，消息按时间倒序排列，每条消息含类型图标、标题、正文、时间、未读态。
3. 面板顶部提供"全部标记为已读"，点击后清空未读角标。
4. 点击单条消息即标记为已读。
5. 消息为空时展示"暂无消息"空状态。

### 4.4 验收标准

- [ ] 存在未读消息时展示数字角标，全部已读后角标消失
- [ ] 下拉面板覆盖上述六类场景消息，各至少一条示例
- [ ] 支持"全部标记为已读"一键操作
- [ ] 支持点击单条消息标记为已读
- [ ] 消息列表可滚动查看，不撑破页面布局

> 说明：当前"提交审核""审核驳回"等动作触发的新增通知为前端示例数据，尚未与实际业务动作打通；真实上线需要在对应动作成功后调用消息中心接口下发通知。

## 需求五：客户主体信息内容补充

### 5.1 背景与问题

"我的账号信息"页面的客户主体信息模块内容较为单薄，仅有主体名称、统一社会信用代码、企业状态三项，无法满足销售/运营对客户资质的了解需要。

### 5.2 需求描述

补充工商信息字段，并为每个字段标注数据来源标签：

| 数据来源标签 | 含义 | 是否可编辑 |
| --- | --- | --- |
| 工商回显 | 根据客户主体名称自动联动查询工商登记信息回填 | 不可编辑 |
| 人工校正 | 由业务/客户手动维护补充的信息 | 可编辑 |
| 系统记录 | 系统自动生成记录，如资料更新时间 | 不可编辑 |

字段清单：客户主体名称（工商回显）、统一社会信用代码（工商回显）、企业状态（人工校正）、法人代表（工商回显）、企业类型（人工校正）、注册资本（工商回显）、所属行业（人工校正）、SOP 行业组（人工校正）、行业梯队（人工校正）、员工规模（人工校正）、注册地址（工商回显）、经营地址（人工校正）、资料更新时间（系统记录）、经营范围/企业简介（人工校正）。

### 5.3 交互说明

1. 客户主体名称变更时，工商回显字段（统一社会信用代码、法人代表、注册资本、注册地址）自动联动查询并回填，不可手动编辑。
2. 人工校正字段由业务/客户手动填写维护。
3. 保存后，"资料更新时间"由系统自动刷新为最新保存时间。

### 5.4 待二期补充事项

企业类型、所属行业、SOP 行业组、行业梯队、员工规模等"人工校正"字段的具体取值范围（下拉枚举选项），本期原型暂以自由文本呈现，取值范围将在二期 PRD 中补充明确定义。

### 5.5 验收标准

- [ ] 工商信息区块展示上述全部字段，每个字段旁标注数据来源标签
- [ ] "工商回显"字段在编辑态下为禁用（只读）状态，仅能通过客户主体名称联动更新
- [ ] "人工校正"字段在编辑态下可自由编辑
- [ ] "资料更新时间"不可编辑，保存后自动刷新为最新时间
- [ ] 非编辑态下字段以标签 + 值的卡片形式展示，来源标签清晰可辨

## 需求六：修改个人信息流程简化（取消审核）

### 6.1 背景与问题

旧版"修改个人信息"需要同时维护联系人姓名/电话/邮箱、填写修改原因，提交后进入"待米播审核"状态，需人工审核通过才生效。但换绑手机号本身已通过短信验证码完成身份核验，再叠加人工审核冗长且无必要。

### 6.2 需求描述

将"修改个人信息"精简为纯"换绑手机号"流程：只需填写新绑定手机号，获取并输入验证码，验证通过后点击确认即可**立即生效**，不再需要米播审核，也不再需要填写联系人信息或修改原因。

### 6.3 交互流程

1. 点击"修改个人信息"，弹出弹窗，展示当前绑定手机号（只读）。
2. 填写新绑定手机号（校验中国大陆手机号格式，且不能与当前绑定手机号相同）。
3. 点击"获取验证码"，验证码发送至新绑定手机号。
4. 输入 6 位验证码，校验通过后显示"验证通过，确认后立即生效"。
5. 点击"确认修改"，绑定手机号立即更新并提示成功，无需等待审核。

### 6.4 验收标准

- [ ] 弹窗仅包含"当前绑定手机号（只读）/ 新绑定手机号 / 验证码"三项，不再展示联系人姓名、电话、邮箱、修改原因字段
- [ ] 验证码未校验通过前，"确认修改"按钮保持禁用
- [ ] 确认修改后立即更新绑定手机号并提示成功，不再展示"待米播审核"状态、审核详情入口及驳回原因等审核相关 UI
- [ ] "账号与联系人信息"模块中的绑定手机号同步展示为脱敏后的新手机号

> 说明：本次简化后，联系人姓名 / 电话 / 邮箱在该弹窗中不再可编辑，页面上仍以只读形式展示。如后续仍需支持编辑联系人信息，需另行规划独立入口，不在本次范围内。

## 需求七：充值失败状态与退款申请

### 7.1 背景与问题

当常规充值处理到"米播进行账户充值"（第 3 步）或特批充值处理到"充值完成"（第 4 步）时，若充值执行失败，此前只以通用"异常"标签展示，客户无法在页面上发起退款操作，需要线下联系客服处理。

### 7.2 需求描述

1. 常规充值第 3 步 / 特批充值第 4 步充值执行失败时，节点标识变红，标签由"异常"更新为**"充值失败"**。
2. 充值任务操作列新增**"退款申请"**按钮，仅当订单处于"充值失败"状态时可点击，其他状态下置灰并提示"仅充值失败状态可申请退款"。
3. 点击"退款申请"后弹出确认弹窗（见需求八）。

### 7.3 验收标准

- [ ] 常规充值第 3 步 / 特批充值第 4 步充值失败时，节点进度条对应分段变红，标签展示"充值失败"
- [ ] 充值任务看板与充值任务列表页的操作列均新增"退款申请"按钮
- [ ] "退款申请"仅在订单状态为"充值失败"时可点击，其余状态下置灰并展示禁用原因提示
- [ ] 点击"退款申请"后弹出退款确认弹窗

## 需求八：退款申请确认弹窗

### 8.1 需求描述

点击"退款申请"后弹出确认弹窗，文案为"由于充值任务失败，您的付款将被原路退回。"弹窗**不提供关闭按钮，也不支持点击遮罩层关闭**，用户必须点击"确认"才能关闭弹窗。

### 8.2 验收标准

- [ ] 弹窗仅展示退款说明文案与充值单号，仅有一个"确认"按钮
- [ ] 弹窗不展示关闭（X）按钮，点击遮罩层不会关闭弹窗
- [ ] 点击"确认"后弹窗关闭并提示"退款申请已提交"
