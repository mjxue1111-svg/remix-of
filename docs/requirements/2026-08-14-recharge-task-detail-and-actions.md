# 需求文档：充值任务详情抽屉与操作项优化

- 所属页面：充值任务列表 / 首页充值任务看板 / 充值详情抽屉
- 版本：二期迭代
- 提出日期：2026-08-14
- 状态：设计中（原型已实现，待评审）

---

## 需求一：详情抽屉移除"查看进度"及与外部入口重复的操作按钮

### 1.1 背景与问题

充值详情抽屉底部此前根据订单节点展示不同的操作按钮，其中：

- "米播进行账户充值中"节点展示"查看进度"按钮，但该按钮未接入实际跳转逻辑，且抽屉内本身已有"进度概览"模块可以查看完整进度，属于冗余入口。
- "充值失败"状态展示"补充材料"按钮，与充值任务列表操作列已有的"退款申请"入口语义冲突——充值失败订单应引导客户走退款流程，而非补充材料重试。
- 特批充值"客户上传付款凭证"状态展示"上传回单"按钮，与列表操作列已有的"继续上传凭证"入口功能重复，容易让客户误以为是两个不同的操作。

### 1.2 需求描述

1. 详情抽屉底部移除"查看进度"按钮（原"米播进行账户充值中" `transferring` / `finance_confirm` 节点触发）。
2. 移除"充值失败"（`transfer_error`）状态下的"补充材料"按钮。
3. 移除特批充值"客户上传付款凭证"（`sp_payment_pending`）状态下的"上传回单"按钮。
4. 保留不变：
   - "充值完成"状态的"查看流水"按钮。
   - "已驳回"（`audit_rejected`）状态的"修改申请"按钮。

### 1.3 验收标准

- [ ] 充值中（`transferring` / `finance_confirm`）状态打开详情抽屉，底部不展示"查看进度"按钮
- [ ] 充值失败（`transfer_error`）状态打开详情抽屉，底部不展示"补充材料"按钮，仅保留"关闭"
- [ ] 特批充值客户上传付款凭证（`sp_payment_pending`）状态打开详情抽屉，底部不展示"上传回单"按钮，仅保留"关闭"
- [ ] 充值完成、已驳回状态的底部按钮展示不受影响

## 需求二：详情抽屉信息模块顺序与内容调整

### 2.1 背景与问题

原抽屉信息模块顺序为：基础信息 → 当前状态 → 付款凭证信息 → 米播进行账户充值 → 进度概览。其中"基础信息"命名与实际展示的账户、金额信息不够贴切；"米播进行账户充值"模块仅展示抽象的转账状态文字，客户更需要能直接看到米播向账户划拨时留存的截图凭证，作为可核验的凭据。

### 2.2 需求描述

1. 模块顺序调整为：**充值账户信息 → 当前状态 → 付款凭证信息 → 进度概览 → 划拨截图**。
2. 原"基础信息"模块更名为"**充值账户信息**"，展示内容不变：充值单号、星图账户、星图账户 ID、充值金额、应付金额、折扣、提交时间。
3. 原"米播进行账户充值"模块替换为"**划拨截图**"模块，展示米播向客户星图账户完成划拨时上传的截图凭证；截图暂未上传或划拨处理中时，展示"处理中"占位状态。

### 2.3 验收标准

- [ ] 详情抽屉内模块自上而下依次为：充值账户信息、当前状态、付款凭证信息、进度概览、划拨截图
- [ ] "充值账户信息"模块字段与原"基础信息"模块一致，仅标题变更
- [ ] "划拨截图"模块在无截图数据时展示"处理中"占位，不报错、不空白

## 需求三：充值任务操作按钮按订单状态重新梳理

### 3.1 背景与问题

此前操作列按钮的展示逻辑分支较多，"继续提交""重新提交付款凭证""提交付款凭证"等按钮在草稿、驳回、失败、未完成等状态下各自有独立判断分支，容易在特定状态下出现按钮堆叠、语义重复或与业务预期不符的问题（例如非失败的未完成订单仍可操作取消/重新提交，与业务口径不一致）。

### 3.2 需求描述

将充值任务按以下 6 种状态重新定义操作列按钮：

| 订单状态 | 操作按钮 |
| --- | --- |
| 草稿 | 继续提交、查看详情、取消订单 |
| 充值完成 | 查看详情、取消订单 |
| 常规充值未完成（非充值失败导致） | 查看详情 |
| 常规充值未完成（充值失败导致，即 `transfer_error`） | 查看详情、退款申请 |
| 特批充值未完成（非充值失败导致） | 查看详情、继续上传凭证 |
| 特批充值未完成（充值失败导致，即 `transfer_error`） | 查看详情、退款申请 |

### 3.3 交互流程

1. 草稿订单点击"继续提交"，打开充值申请表单并预填已保存内容。
2. 特批充值未完成（非失败）订单点击"继续上传凭证"，打开付款凭证上传弹窗。
3. 充值失败（常规/特批）订单点击"退款申请"，进入需求四的退款流程（沿用已有"退款申请确认弹窗"）。
4. 任意状态点击"查看详情"，打开充值详情抽屉（只读展示，不重复暴露上述操作）。
5. "取消订单"入口收纳于操作列的"…"更多菜单中，仅草稿、充值完成两种状态可点击，其余状态置灰并提示原因。

### 3.4 验收标准

- [ ] 草稿状态操作列展示"继续提交""查看详情"，"…"菜单中"取消订单"可点击
- [ ] 充值完成状态操作列仅展示"查看详情"，"…"菜单中"取消订单"可点击
- [ ] 常规充值未完成（非失败）状态操作列仅展示"查看详情"，不展示其他操作按钮，"取消订单"置灰
- [ ] 常规 / 特批充值失败（`transfer_error`）状态操作列展示"查看详情""退款申请"，"取消订单"置灰
- [ ] 特批充值未完成（非失败）状态操作列展示"查看详情""继续上传凭证"，"取消订单"置灰
- [ ] 首页充值任务看板与充值任务列表页的操作列逻辑保持一致

## 需求四：充值完成状态取消订单二次确认

### 4.1 背景与问题

原"取消订单"仅在草稿及尚未进入处理流程的订单可用，"充值完成"状态订单不可取消。业务需要允许已完成订单发起取消并同步走退款流程，但完成状态意味着资金已到账，取消动作影响更大，需要与草稿取消（尚未产生实际资金流转）区分，增加二次确认防止误操作。

### 4.2 需求描述

1. "取消订单"入口在**草稿**、**充值完成**两种状态下可点击，其余状态置灰并提示"当前订单状态暂不可取消"。
2. 草稿状态点击"取消订单"，沿用原有"取消充值订单"弹窗（选择取消原因、备注说明、确认勾选后"确认取消"）。
3. 充值完成状态点击"取消订单"，弹出新的二次确认弹窗：
   - 文案："是否取消订单并申请退款？"
   - 仅提供"**关闭**"与"**退款申请**"两个选项。
   - 点击"关闭"：直接关闭弹窗，不产生任何操作。
   - 点击"退款申请"：提示"退款申请已提交，米播将原路退回款项"，并关闭弹窗。

### 4.3 验收标准

- [ ] 充值完成状态的订单在操作列"…"菜单中"取消订单"可点击（此前为置灰不可点击）
- [ ] 充值完成状态点击"取消订单"弹出"是否取消订单并申请退款？"二次确认弹窗，而非原有取消原因表单
- [ ] 该弹窗仅有"关闭""退款申请"两个按钮，无第三种关闭方式（无右上角关闭按钮，点击遮罩层不关闭）
- [ ] 点击"关闭"或"退款申请"后，弹窗均立即关闭
- [ ] 草稿状态点击"取消订单"仍打开原有取消原因表单弹窗，不受本次改动影响
